## 💸 토큰 절약 운영 규칙 (2026-09-17 실측 근거)

## 🚨 AI 에이전트 10대 금기 사항 (Strict Negative Constraints)

1. **디렉토리/파일명 임의 생성 금지 ❌**:
   * 모든 최종 산출물은 `{영상폴더}/v2/out/` 에, 중간 작업물은 `{영상폴더}/v2/out/_work/` 에 격리한다.
   * 비디오 파일명은 반드시 `{ID}_{한글제목_공백은_언더바}.mp4` (예: `A_다_후원한다더니_29만_원이_왔어요.mp4`)로 명명한다.
2. **Whisper Naive Offset 단독 사용 금지 ❌**:
   * 기본 offset은 0.3~0.5초 앞서는 오차가 있으므로, 반드시 `--dtw large.v3 --no-flash-attn` 기반 센티초 단위 `t_dtw` 정밀 타임스탬프를 적용한다.
3. **`check_chunks.py` 기계 검증 생략 금지 ❌**:
   * `check_chunks.py` 실행 결과 터미널에 `✅ 스트림 일치` 및 `✅ 자막 레이아웃 통과`가 모두 뜨지 않으면 Stage B 렌더링으로 절대 넘어갈 수 없다.
4. **자막 표준 사양 임의 변경 금지 ❌**:
   * 수치의 정본은 **플랜 템플릿의 `subs` 블록**과 **§화면 레이아웃 스펙 요약** 두 곳뿐이다(P4). 여기에 다시 적지 않는다.
   * 바꾸면 안 되는 성질: **본문은 한글 단독·무조건 1줄**(2줄 줄바꿈 절대 금지, 영문 병기 없음),
     **상단 제목은 인물 머리 위에 영상 내내 고정**.
5. **회중 리액션(웃음소리/박수) 절단 금지 ❌**:
   * 펀치라인 직후 회중 웃음/박수 구간(2~3초, -34~-41dB)은 무음 감지기 삭제를 방지하기 위해 `plan.json`의 `"preserve": [[start_sec, end_sec]]`에 원본 절대시간으로 명시한다.
   * ★`preserve`는 반드시 `segments` 범위 안에 있어야 한다 (벗어나면 변환이 비어 로그 없이 통째로 무시됨).
6. **화면 동결 및 컷 직후 인물 이탈 금지 ❌**:
   * 인물 추적은 480 px/s 등속 글라이드로 부드럽게 패닝한다.
   * 컷이 바뀐 첫 프레임부터 인물이 화면 중앙에 있어야 한다 (스무딩·보간은 샷 경계 안에서만 적용).
7. **자막 번인 영상에서 썸네일 프레임 추출 금지 ❌**:
   * 썸네일 배경은 반드시 자막이 0% 들어간 클린 마스터(`_work/{slug}_master.mov`)에서 `extract_clean_frames.py`로 추출한다.
8. **묵은 `_raw.mp4` 위에 재렌더 금지 ❌**:
   * 재렌더 전 반드시 `rm -f {영상폴더}/v2/out/_work/{slug}_raw.mp4`를 실행한다. (Gate 8 G-F 길이차로 사후 검출)
9. **자막 레이아웃 넘침 절대 금지 ❌**:
   * 한 행이 안전폭을 넘으면 좌우 여백을 뚫고 잘린다. 글자 수는 어림값이고 **판정은 항상 픽셀 폭**이다.
   * 넘치면 **청크를 2개로 분할한다.** `\N` 로 2행을 만드는 건 금기 4 와 충돌하므로 금지.
   * 허용 폭의 정본은 `safe_area.py`(P4). 캔버스 끝까지 쓰면 플랫폼 재생 화면에서 잘리므로 좌우 여유를 둔다.
10. **말더듬 및 불필요한 중복 발화 방치 금지 ❌**:
    * `silence_cut.py`는 무음만 자르므로, 유음 반복 어휘("그래서 제가 그래서 제가"), 말더듬("우리가 우리가"), 중복 문장 재시작("드라마 볼 시간인데 성경 읽고 이거 너무 너무 있어요")은 반드시 `cut_fillers.py`와 전사 통독을 거쳐 원본 구간에서 100% 잘라내고 Stage A를 재실행해야 한다. 말더듬이나 반복 발화가 남은 상태로 영상을 완성하면 무조건 반려된다.

## 🧭 검증 설계 원칙 (P1~P5)

결함은 대개 "게이트가 없어서"가 아니라 **게이트가 그 결함을 구조적으로 못 보게 생겨서**
통과한다. 게이트를 만들거나 고칠 때, 그리고 "게이트는 통과했는데 결과물이 이상하다" 는
말을 들었을 때 아래를 먼저 적용한다.

* **P1 — 집계 지표 하나로 판정하지 않는다. 집계 상한과 단일 항목 상한을 같이 건다.**
  비율·평균·총합·유사도는 국소 결함 하나를 전체 길이로 희석한다.
  "총합 N% 이하" 형태의 기준을 볼 때마다 **"가장 나쁜 한 건 <= X"** 가 옆에 있는지 확인하고,
  없으면 그 게이트는 미완성이다.
* **P2 — "있어야 할 말"과 "없어야 할 소리"는 검증 수단이 다르다.**
  전사 기반 지표(재전사 유사도, 전사문 검색)는 텍스트로 정규화된 결과만 본다.
  더듬은 조각·들숨·조각 발성·군더더기 소리는 애초에 전사문에 안 적히므로
  **전사 계열 지표로는 원리상 못 잡는다.** 이 부류는 오직 **진폭(파형)** 으로 판정한다.
  유사도가 높다는 사실을 "군더더기가 없다"의 근거로 쓰지 않는다.
* **P3 — 화면에 그려지는 요소는 하나도 빼지 않고 잰다.**
  검사기가 특정 스타일·특정 트랙만 골라 재면 나머지는 영구 사각지대가 된다.
  스타일마다 폰트 크기도 여백도 다르므로 **안전폭은 그 스타일의 값에서
  `1080 - MarginLR x 2` 로 따로 계산**한다.
* **P4 — 수치 규칙의 정본은 검사기다. 문서는 검사기를 가리킨다.**
  같은 수치를 문서 여러 곳에 적으면 갱신이 한 곳에만 들어가 나머지가 서로를 반박하고,
  그 순간부터 문서 전체가 신뢰를 잃는다. **문서와 검사기가 다르면 검사기가 정답**이고
  문서를 고친다. 새 규칙은 먼저 검사기에 넣고, 문서에는 한 줄로만 적는다.
* **P5 — 검출 0건은 "깨끗함"이 아니라 "측정계 확인 필요"로 읽는다.**
  로그 레벨·필터 조합·스타일 필터 때문에 결과가 조용히 비는 경우가 있다.
  0건이 나오면 반드시 걸리는 입력으로 한 번 되짚어 측정계가 살아 있는지 확인한 뒤에만
  "없다"고 보고한다.

## 🌐 크로스플랫폼 동적 도구 탐색 (`env_discovery.py`)

파이프라인 실행 시 `env_discovery.py`가 아래 우선순위로 도구와 모델을 동적으로 자동 감지합니다:
1. **환경변수**: `WHISPER_BIN`, `WHISPER_MODEL`, `YUNET_MODEL`, `FFMPEG_BIN`, `FFPROBE_BIN`
2. **로컬 프로젝트**: `./models/` (예: `models/yunet.onnx`, `models/ggml-large-v3.bin`)
3. **시스템 PATH & 패키지 매니저**: Homebrew(`/opt/homebrew/bin`), APT(`/usr/bin`), `~/.local/bin`
4. **글로벌 캐시 디렉토리**: `~/.cache/whisper.cpp/`, `~/.cache/shorts_autopilot/`

*실행 명령어 예시의 `python3`는 OpenCV(cv2), NumPy, Pillow가 설치된 가상환경 파이썬을 가리키며, 스크립트 경로는 프로젝트 기준 상대경로(`scripts/shorts_v2/`)로 표기합니다.*

|---|---|

* **꼬리 페이드아웃 자리 확보**: 마지막 세그먼트는 `[..., 발화끝 + 1.2s]`로 잡고, `preserve`에 `[발화끝, 발화끝 + 1.2s]`를 명시한다.
* **카메라 미세 조정 (`track`, 선택 사항)**: 카메라가 산만하거나 구도가 튈 때만 `plan.json`에 `track` 블록을 추가한다 (없으면 480 px/s 기본값):

| 키 | 기본값 | 뜻 | 언제 만지나 |
|---|---|---|---|
| `pan_speed` | 480 | 패닝 속도(px/s) | 카메라가 산만하면 낮춘다 (100 근처까지) |
| `static_spread` | 150 | 정적 판정 이동폭(px) | 미세하게 계속 흔들리면 올린다 / G-D 이동비율이 모자라면 낮춘다 (50 근처까지) |

| `carry_ratio` | 0.25 | 샷 경계 뒤에도 얼굴이 직전 크롭 중앙에서 crop_w×비율 안이면 구도를 이어 씀(이동 샷은 0.40). 2026-09-17 이음매마다 200~460px 순간이동하던 결함 수정 | 거의 안 만진다 |
| `static_mindur` | 1.8 | 이 길이(초) 미만인 샷은 무조건 고정 | 짧은 샷이 자꾸 움직이면 올린다 |

## 🔄 전 공정 8단계 워크플로우 및 실행 가이드

### [Phase 0] 유튜브 링크를 받았을 때 — 다운로드 & 설교 구간 컷 (Gate 0)

오너가 **유튜브 링크를 주며 쇼츠를 만들라고 하면** 묻지 않고 다운로드 → 설교 부분만 컷 → 전체 전사 →
Phase 1 까지 이어간다(오너 2026-09-15). 소재를 함께 주면 그 소재가 **내용으로 들어간** 편을 만든다(훅 문구가 아님).

1. **작업 폴더**: `~/Documents/HaolamShorts/{예배날짜 YYYY-MM-DD}_{회차 요약}/` (예: `2026-09-13_테슈바32일차`).
   날짜는 영상 제목의 예배 날짜를 쓴다. 원본은 `{영상폴더}/source/` 에 받는다.
2. **다운로드** (`/opt/homebrew/bin/yt-dlp`). 해상도 지정이 없으면 **있는 것 중 최고 해상도**
   (4K → 1440p → 1080p 순으로 자동), 영상은 VP9, 오디오는 **Opus(251) 최고 비트레이트**. 포맷 ID 를 손으로 고르지 않는다.
   ```bash
   yt-dlp --no-playlist \
     -f 'bv*[vcodec!^=av01][vcodec!^=vp09.02]+ba[acodec=opus][format_id!*=drc]/bv*[vcodec!^=av01]+ba[format_id!*=drc]/b' \
     -S 'res,vcodec:vp9,acodec:opus,abr' --merge-output-format mp4 \
     -o "{영상폴더}/source/%(title)s.%(height)sp.%(ext)s" "{URL}"
   ```
   * ⚠ **AV1(`av01`) 금지** — 이 맥(M1 Pro)은 AV1 하드웨어 디코드가 없어 추적·렌더가 극단적으로 느려진다.
   * `vp09.02`(VP9 HDR)·`-drc`(음량 압축본 오디오)도 뺀다.
   * Opus 를 mp4 에 담아도 파이프라인은 오디오를 PCM 으로 풀어 쓰므로 문제없다(2026-09-18 실측: vp9 3840x2160 + opus 48k 2ch 병합·wav 추출 OK).
     단 QuickTime 은 VP9·Opus mp4 를 못 튼다 — 확인은 IINA/VLC 로.
3. **설교 시작·끝 찾기** — 챕터·설명란 타임스탬프를 먼저 보고, 없으면 받아쓰기로 찾는다.
   ```bash
   yt-dlp --skip-download --no-playlist --print "%(chapters)j" --print description "{URL}"
   ffmpeg -v error -y -i "{원본}" -vn -ar 16000 -ac 1 "{영상폴더}/full16k.wav"
   # 설교가 시작될 법한 범위를 30초 간격·15초 길이로 받아써 설교자 첫 문장 위치를 찾는다 (끝도 같은 방식)
   for t in $(seq {탐색시작초} 30 {탐색끝초}); do
     ffmpeg -v error -y -ss $t -t 15 -i "{영상폴더}/full16k.wav" /tmp/probe.wav
     echo "$t $({whisper-cli} -m {ggml-large-v3.bin} -f /tmp/probe.wav -l ko -nt -np | tr '\n' ' ')"
   done
   ```
   * 설교 앞 찬양·광고, 설교 뒤 마무리 기도 후 찬양 전환이 섞이지 않게 경계를 잡는다.
4. **설교 구간 컷(무재인코딩) + 전체 전사**
   ```bash
   cd "{영상폴더}"
   ffmpeg -v error -y -ss {시작초} -to {끝초} -i "source/{원본}.4k.mp4" -c copy -avoid_negative_ts make_zero sermon_4k.mp4
   ffmpeg -v error -y -i sermon_4k.mp4 -vn -ar 16000 -ac 1 full.wav
   {whisper-cli} -m {ggml-large-v3-turbo.bin} -f full.wav -l ko -osrt -of full_transcript
   ```
   * 이후 모든 시각(plan `segments`·`preserve`)은 `sermon_4k.mp4` 기준이다. `-c copy` 라 시작이 키프레임까지 몇 초 당겨질 수 있지만 문제없다.
   * 보고서에 **"전체 영상 시각 = 설교 파일 시각 + {시작초}"** 를 적는다.
5. Phase 1 부터 `--src sermon_4k.mp4` 로 진행한다.

* 🛑 **Gate 0 통과 기준**: `ffprobe` 로 해상도·코덱 확인(av1 아님) + 설교 시작·끝 첫마디를 받아쓰기로 확인 + `sermon_4k.mp4` 길이 확인.

### [Phase 1] 기획 & 플랜 작성 (Gate 1)

1. **서사 구조**: 3~5초 내 도발/웃음/호기심 훅 ➔ 본질적 이유(R) ➔ 구체적 장면(E) ➔ **타협 없는 복음적 결단 및 선포(O)** 로 종결 (단순 상황 설명/개념 정의 종결 절대 금지).

2. ★**한 편이 그 자체로 완결된 메시지여야 한다.**
   설교 흐름에는 부연이 많지만, 쇼츠는 **떼어놓고 봐도 앞머리를 자른 느낌이 없어야** 한다.
   * **판정법**: 이 영상만 처음 본 사람이 "왜 그 말이 나왔는지" 모르면 탈락이다.
   * **맥락은 설교 다른 위치에서 끌어와 붙인다.** 원본 순서를 거슬러도 된다 —
     `extract_segments.py` 는 `segments` 를 적힌 순서대로 이어 붙이고, segmap 이 역매핑을 감당한다.
   * ⚠ **정의·배경을 훅 앞에 붙이지 않는다.** 훅이 뒤로 밀리면 쇼츠에서 제일 손해다.
     교리적 근거가 필요하면 **훅 바로 뒤에 한 문장만** 끼우고, 설명이 그보다 길어지면
     **그 대목은 별도 안으로 뺀다.**

3. ★**오너가 준 소재는 내용이다 — 훅으로 끌어오지 않는다** (오너 2026-10-03).
   소재의 결론 문장(예: "똥을 꽃길로 만드는 게 내 기도")을 맨 앞에 붙이고 근거를 뒤로 돌리면 반려된다
   ("똥이 왜 꽃길이 되는지가 앞에 나와야"). **원본 흐름대로 '왜'가 먼저 오고 소재가 결론으로 오게** 짜고,
   훅은 그 흐름의 첫 대목에서 고른다.

4. ★**훅은 셋 중 하나로 만든다.**
   | 방식 | 쓸 때 |
   |---|---|
   | **결론을 맨 앞으로** | 마지막 선포가 그 자체로 강할 때 |
   | **실사례·웃긴 이야기** | 대화체 일화가 있을 때 |
   | **질문** | 듣는 사람을 직격할 때 |

   * ⚠ **접속어로 시작 금지**: "그러면/그래서/근데/그 정도로/아니 근데" 에서 시작하면 훅이 죽는다.
     **펀치라인 첫 음절**에서 시작한다.
   * **컷 지점은 반드시 기계로 검증한다.** 전사문 타임스탬프는 0.3~0.5초 앞서므로 그대로 쓰면 첫 음절이 잘린다.
     ```bash
     # ① 파형에서 발화 시작 후보 뽑기
     ffmpeg -hide_banner -nostats -i full.wav -af silencedetect=noise=-32dB:d=0.18 -f null - 2>&1 | grep silence_
     # ② 후보 지점을 짧게 잘라 실제로 무슨 말이 들리는지 확인
     ffmpeg -v error -y -ss {후보} -t 8 -i full.wav -ar 16000 -ac 1 /tmp/probe.wav
     {whisper-cli} -m {model} -f /tmp/probe.wav -l ko -nt -np
     ```
     ②에서 원하는 첫 마디로 시작하지 않으면 채택하지 않는다.

5. ★**반려된 소재는 다시 쓰지 않는다.**
   오너가 제안을 반려하면 **훅·컷만 고쳐 같은 소재를 다시 내밀지 않는다.**
   설교의 **다른 대목에서 새로 뽑는다.** 반려된 소재 목록을 보고서에 남겨 다음 회차에 또 고르지 않는다.

6. **한 영상에 화자가 여럿일 수 있다.** 설교 뒤 마무리 권면 등 화자가 바뀌는 구간이 있으므로,
   안별로 화자를 확인하고 보고서에 명시한다.

7. **세그먼트 추출 & preserve 지정**: 회중 웃음 구간(실제 웃음만 2~3초 좁게) 및 마지막 세그먼트 페이드 꼬리를 `preserve`에 원본 절대시간으로 지정.

* 🛑 **Gate 1 통과 기준**: 완결된 OREO 선포 서사 + **떼어놓고 봐도 완결** + 훅이 3종 중 하나 + 접속어 시작 아님(기계 검증) + preserve 명시 + 선두 발화 직전 컷팅.

### [Phase 2] Stage A 실행 (컷 추출 + 무음 제거 + DTW 전사 + 인물 추적) (Gate 2)

> 🚫 **플랜 두 개를 같은 `--outdir` 로 동시에 돌리지 않는다.** `extract_segments.py` 와 `silence_cut.py` 는
> `_work/seg_000.mov`, `_concat_list.txt`, `_silence_batch_000.mov` 같은 **플랜 구분 없는 공용 임시 파일명**을 쓴다.
> 병렬로 돌리면 서로 덮어써 `raw.mov` 가 깨지고(`Invalid NAL unit size` / `Error splitting the input into NAL units`)
> silence_cut 단계에서 exit 1 로 죽는다. 로그가 ffmpeg 디코드 오류로 보여 원인을 헤매게 된다. **반드시 순차 실행.**

```bash
python3 scripts/shorts_v2/run_pipeline.py \
  --src "{원본_영상_경로.mp4}" --plan "{영상폴더}/plans/plan_{ID}.json" \
  --outdir "{영상폴더}/v2/out" --stage a
```
* **간투사·반복 발화·말더듬 제거 필수 절차**:
  `silence_cut.py` 는 무음만 자른다. 유음 간투사("어", "그", "이제"), 같은 말 반복
  ("그래서 제가 그래서 제가"), 말을 끊고 다시 시작한 자리("용서했는… 용서했다니까"),
  더듬은 조각("그런 글을 자격도 없습니다")은 못 잡으므로 **아래 ①②를 모두** 돌린다.

  ① **기계 검출** — 소리 있는 갭 후보 (`MIN_VOICE = 0.30`):
  ```bash
  python3 scripts/shorts_v2/find_filler.py "{영상폴더}/v2/out/_work/{slug}"
  ```
  회중 웃음·박수와 세그먼트 이음매도 여기 걸린다. `preserve` 로 지정한 구간은 무시한다.
  * ★**전사문에 안 적히는 소리는 시간으로 자른다**(P2). 첫 발화 앞 조각 발성·들숨, 발화 중 긴 무음은
    글자 색인이 없어 `--cut` 으로 표현할 수 없다. `--gaps` 가 master.wav 진폭으로 자동으로 찾고
    (무음 판정·상한은 G-H 와 같은 잣대를 import 한다 — P4), 더듬은 첫 음절처럼 귀로 찾은 구간은
    `--cut-sec` 에 master 초로 넣는다. `preserve` 와 겹치거나 세그먼트 이음매를 가로지르는 구간은 스스로 건너뛴다.
    ```bash
    python3 scripts/shorts_v2/cut_fillers.py --work "{영상폴더}/v2/out/_work" --slug "{slug}" \
        --plan "{영상폴더}/plans/plan_{ID}.json" --gaps --cut-sec {a:b ...} --dry-run
    ```
    * ⚠ zsh 는 따옴표 없는 변수를 단어로 쪼개지 않는다. `--cut-sec` 값을 변수 하나에 담아 넘기면
      통째로 한 인자가 되어 argparse 가 거부한다 — 인자를 풀어서 쓴다.

  ② **전사 통독** — 기계가 못 잡는 반복·더듬은 글자 스트림을 읽어 눈으로 찾는다.
     `--list` 끝에 **더듬·재시작 의심 목록**이 나온다(2026-09-17: "용암불이 막 용암이"를 통독에서 놓쳐 오너가 재요청).
     목록의 모든 항목을 오디오로 확인해 더듬이면 자르고, 아니면 보고서에 "확인·유지"로 남긴다. 목록을 건너뛰면 Gate 2 불합격:
  ```bash
  python3 scripts/shorts_v2/cut_fillers.py --work "{영상폴더}/v2/out/_work" --slug "{slug}" --list
  python3 scripts/shorts_v2/cut_fillers.py --work "{영상폴더}/v2/out/_work" --slug "{slug}" \
      --find 그래서제가 그런글을
  ```

  찾은 글자 색인 구간을 그대로 잘라낸다. master 시간 ➔ raw ➔ src(원본 절대시간) 역매핑과
  `plan.segments` 분할을 스크립트가 처리한다:
  ```bash
  python3 scripts/shorts_v2/cut_fillers.py --work "{영상폴더}/v2/out/_work" --slug "{slug}" \
      --plan "{영상폴더}/plans/plan_{ID}.json" --cut 36:44 54:61 207:209 --dry-run
  ```
